# MailPro 计划

注重隐私的 Windows 桌面邮件客户端：接入 Gmail、Outlook / Hotmail 和其他 IMAP 邮箱；默认不加载任何远程内容，发件人无法通过邮件得知你何时打开、在哪里打开。

## 已定决策

| 项 | 决定 |
|---|---|
| 平台 | 只做 Windows（WebView2、凭据管理器）；gpui 跨平台，以后可扩 |
| 界面 | Rust + gpui-pre 0.3.9 / gpui-component 0.7.3（与 PushRight 同版本） |
| 正文渲染 | 嵌入 gpui 窗口的 WebView2 子窗口，锁死：不跑脚本、所有网络请求本地拦截 |
| 协议 | 全部 IMAP + SMTP；不支持 POP3（不同步已读状态） |
| Gmail | 应用专用密码；另允许填自己的 OAuth client |
| Outlook / Hotmail | OAuth2：Entra 注册的公共客户端（仅个人账户），系统浏览器登录 + PKCE + 回环地址；IMAP、SMTP 都用 XOAUTH2 |
| 代理 | 邮箱连接固定走代理，不漏真实 IP（细节见第三步） |
| 打开链接 | 用用户自选的浏览器：系统默认、指定程序或 AdsPower 环境（SunBrowser），见第四步 |
| 写信 | MVP 只做纯文本与引用回复，HTML 编辑以后 |
| 本地缓存 | 邮件头全量同步，正文按需下载并缓存；数据库不另加密，凭据进 Windows 凭据管理器 |
| 端到端加密 | 不在 MVP |
| 已读同步 | 走 IMAP 服务器标记，多台电脑自动一致；本软件自己的设置用导出 / 导入文件 |
| 遥测 | 无遥测、无崩溃上报 |

## 目录

```
crates/core    邮件逻辑，不依赖界面：解析、HTML 清洗、链接清洗、IMAP、SMTP、存储
crates/app     gpui 界面 + WebView2 正文查看器
tests/privacy  跟踪测试邮件 + 本地计数服务器
```

## 隐私防线（正文查看器）

1. HTML 白名单清洗（ammonia）：删 script、iframe、object、form、link、meta、base；远程图片（含 CSS 里的）换成本地编号地址，默认不加载（第四步）；`cid:` 内嵌图片改成本地地址；链接地址换成本地编号，原地址留在程序里。
2. CSP：`default-src 'none'`，只放行本地地址的图片和 data 图片、内联样式。
3. WebView2 网络拦截：所有请求进同一个处理器，只有本地地址有响应，其余本地返回 403，内核自己不出网；允许加载的远程图片由程序经代理代取后交给它。
4. WebView2 设置：关脚本、关 SmartScreen（不把网址发给微软）、关状态栏、关自动填充、无痕模式；所有页面跳转取消，由程序处理。

## 步骤

每步做完都能单独运行和验证。

1. **正文查看器原型**（已完成）：gpui 窗口嵌 WebView2，打开一封 .eml，走完上面四道防线。
   - 验证：清洗的单元测试通过；`tests/privacy/tracking.eml` 含 30 多种跟踪手段，无防护的 headless Chrome 打开后计数服务器收到 31 种；MailPro 打开同一封，命中 0；内嵌图片、中文排版正常；点链接被拦下，只把原地址报给界面。
   - 复现：`python tests/privacy/tracker.py serve <log>` 起计数服务器，再用 `scripts/drive.ps1` 不抢焦点地启动并截图（用法见脚本头部）。
2. **账号与 IMAP 同步**（已完成）：Gmail（应用专用密码）、Outlook / Hotmail（浏览器登录，XOAUTH2）、其他 IMAP 邮箱（手填服务器，只走 TLS）；SQLite 存邮件头和标记；IDLE 实时推送；已读标记回写服务器。
   - 同步规则：全部文件夹的邮件头全量同步；Gmail 按 IMAP 文件夹原样存（All Mail 也同步，不去重）；首次同步从新到旧分批拉，断了下次接着补；收件箱 IDLE 实时，IDLE 安静 25 秒就结束再重新发起（有的代理约 60 秒掐断空闲连接，实测 Clash 上游的 ISP SOCKS5 如此），全部文件夹每 5 分钟同步一次；列表顶栏的刷新按钮或 F5（焦点在正文里也算）让每个账号立即同步全部文件夹：连着的不断开、直接同步，等重连的立即重连，取不到密码的再取一次，Outlook 授权失效的跳过；按钮转圈到每个账号这一轮同步完或出错为止，其间再按无效；服务器支持 CONDSTORE 时只拉改过的标记。列表不显示正文摘要。正文按需下载，原始邮件存进 SQLite，不清理。标已读先改本地并记待写回，同步该文件夹时写回，邮件已被删就丢弃。断线重连从 5 秒起翻倍，封顶 5 分钟，一直重试。
   - 代码：`crates/core` 的 `store`（SQLite，`%LOCALAPPDATA%\MailPro\mail.db`）、`imap`（同步、IDLE）、`cred`（凭据管理器）、`auth`（Outlook 登录和令牌）；验证工具 `mailpro-cli`（用法见文件头）。
   - 验证：两个真实账号的收件箱与网页版一致；一边标已读，另一边几秒内变化。本地部分由 `crates/core/tests/sync.rs` 对 GreenMail 测试服务器验证（跑法见文件头）；GreenMail 不推送其他连接改的标记，“另一边几秒内变化”只能用真实账号验证。
   - 现状：Gmail 和手填服务器部分已完成，真实 Gmail 验证通过：各文件夹数量与网页版一致；本地标已读 2 秒内写回；网页改标记、新信进收件箱都在几秒内推到本地；其他文件夹随 5 分钟同步跟上；Gmail 支持 CONDSTORE，只拉改过的标记。Gmail 自填 OAuth client 不在这一步。
   - Outlook / Hotmail：Outlook.com 的 IMAP 只收 XOAUTH2（`LOGINDISABLED`，密码登录回 `Basic authentication is disabled`），网页版设置里的 IMAP 开关要打开。服务器固定：`outlook.office365.com:993`（隐式 TLS），发信 `smtp-mail.outlook.com:587`（STARTTLS）。Outlook 不支持 CONDSTORE，每次同步拉全部标记。
   - Outlook 应用：Entra 注册的 MailPro，仅个人 Microsoft 账户，公共客户端（移动和桌面），回调 `http://localhost`，没有客户端密码；Client ID 在 `auth.rs`。端点 `login.microsoftonline.com/consumers/oauth2/v2.0`；scope 为 `https://outlook.office.com/IMAP.AccessAsUser.All`、`https://outlook.office.com/SMTP.Send`、`offline_access`。
   - Outlook 登录：授权码 + PKCE（S256）。本机在 `127.0.0.1` 和 `[::1]` 的同一个随机端口临时监听，`redirect_uri` 为 `http://localhost:{端口}`（localhost 回调不比端口）；授权地址带 `login_hint=邮箱`、`prompt=select_account`。回调核对 state，不符的请求（含 favicon）回 404、接着等；用户拒绝或授权出错时浏览器显示失败页，原因报给对话框。5 分钟没回来算超时，关掉对话框即取消；成功、失败、超时、取消后监听都关掉。拿到令牌先用这个邮箱试登录 IMAP，通过才存。授权地址按左栏“浏览器”菜单打开（系统默认、指定程序或 AdsPower 环境），登录页的网络即该浏览器的网络（AdsPower 环境走环境自己的代理）；只有回调走本机回环。
   - Outlook 令牌：刷新令牌存凭据管理器（`MailPro/邮箱`，和密码同一处），刷新时拿到新的就换掉；访问令牌只在内存，过期前 5 分钟刷新，同一邮箱的同步连接、后台操作连接和发信共用一份，刷新串行。令牌请求经该邮箱的 SOCKS5 代理，代理连不上直接报错，不退回直连；没设代理则直连。令牌不进日志。多个 Outlook 邮箱共用一个 Client ID，各自登录、各存一份令牌、各自同步。
   - Outlook 授权失效：令牌端点回 4xx 且带 `error`（`temporarily_unavailable` 除外，如 `invalid_grant`）即失效：停止同步、不再重连，左栏显示“授权已失效”，在账号设置里点“重新登录”；网络错误、5xx 照常退避重连。
   - Outlook 现状：PKCE（RFC 7636 向量）、回调处理、令牌响应、XOAUTH2 对假服务器的单元测试通过；真实登录、刷新、同步、发信、失效后重新登录待用户实测。
3. **主界面与代理**（已完成）
   - 代理：每个邮箱单独设 SOCKS5 代理（`主机:端口`，不带用户名密码），域名交给代理解析，本机不查 DNS；代理连不上直接报错，绝不退回直连；没设代理的邮箱直连，设置里标“直连”警示。MailPro 自己的连接（IMAP、第六步的 SMTP、Outlook 的令牌请求）都走它；点链接后和 Outlook 登录页的流量归浏览器自己管。
   - 界面：三栏（账号和文件夹 / 邮件列表（虚拟列表）/ 阅读区），栏宽可拖。左栏按账号分组：账号行有展开箭头和首字母圆标（色相按账号 id 取黄金分割步进），点它收起 / 展开；收起时显示收件箱未读数和断线红点，正在看的文件夹在里面时账号行高亮；收起状态存设置 `collapsed`，重启后保持。账号行拖到另一个账号上即排到它的位置，顺序存设置 `order`（空格分隔的 id），没排过的按添加顺序接在后面。收件箱 30 分钟内收到过邮件（按 INTERNALDATE，已读也算，其他文件夹不算）时账号行泛光：淡淡的强调色底加一圈柔光，到点自动熄灭（只在最早熄灭的时刻排一次重画，不逐帧刷新）。文件夹、附件、星标、设置等用 Lucide 线条图标（gpui-kit-assets 的 `AllAssets`）。列表顶部显示文件夹、账号和封数，选中行左侧一条主题色竖条。阅读区头部为主题、发件人与时间、远程资源提示条（盾牌图标，加载按钮在右）。打开邮件即标已读；Gmail 系统文件夹按界面语言显示，固定顺序为收件箱、已加星标、重要、已发送、草稿、所有邮件、垃圾邮件、已删除，再接自建标签；添加账号对话框填邮箱、应用专用密码、代理，非 Gmail 再填服务器和端口；列表一行显示未读圆点、发件人、主题、时间、附件、星标（只显示）；界面中英双语，语言和深浅色默认跟随系统；左栏底部为添加账号，浏览器、语言两个图标按钮（悬停出文字）。
   - 外观：和 PushRight 同一套设计令牌（`crates/app/src/theme.rs`）：暖调的象牙白与炭黑，内容区、左栏、浮起控件三层底色；全应用唯一的强调色取图标粉，当文字和线条用的一档深色主题取亮（`#f472b6`）、浅色取深（`#be185d`），压着白字的底色（主按钮、未读圆点）两个主题都是 `#db2777`；选中行是强调色 12% 的淡底，选中的文件夹字和图标也用强调色。字体：控件 Segoe UI Variable，标题和名字（阅读区主题、列表顶部文件夹名、对话框标题）思源宋体，给人读的整段话（空状态、说明）霞鹜文楷；两套字体由 `scripts/fonts.ps1` 下载（不进 git，约 50 MB），安装到 exe 旁的 `fonts` 目录，找不到时退回系统字体。系统标题栏经 DWM 跟应用深浅色一致。
   - 深色正文：深色时 WebView2 带 `--enable-features=WebContentsForceDark`（Chromium 的自动深色：浅色底变深、照片和彩色块基本保持），页面没写底色处用界面底色。这个参数只能在建内核时给，系统换深浅色时关掉旧查看器重建；两种参数的内核不能共用数据目录，分别放 `WebView2` 和 `WebView2Dark`。
   - 代码：`crates/core` 的 `engine`（后台线程：每个账号一条常驻同步连接，另一条按需连接取正文、写回标记、移动删除；界面只发命令、收事件）；`crates/app` 的 `view`（三栏）、`i18n`（中英文案，选择存在数据库 `setting` 表）、`webview`（整个程序一个 WebView2，换邮件只换内容）。程序带 `.eml` 参数时直接显示这封，供隐私测试用。
   - 验证：上万封邮件的文件夹滚动流畅（用生成的 5 万封假邮件头测试库测帧耗时）；挂代理时 MailPro 只连代理端口，本机 DNS 缓存里没有邮件服务器域名；代理端口填错时连接直接失败。
   - 现状：全部验证通过。5 万封的收件箱在后台读入约 38 ms，滚动时每帧 CPU 耗时中位 2.8 ms、p95 7.2 ms（release）；真实 Gmail 经代理同步、显示正文，进程只连 127.0.0.1:7898，DNS 缓存里没有 Google 域名；添加账号时代理填 127.0.0.1:1 直接报错；`tracking.eml` 在新界面里计数服务器命中仍为 0；开对话框时正文藏起，关掉后恢复；中英切换、账号设置改代理后重连均正常。界面改用 PushRight 设计令牌后截图核对：深色下正文随之变深，泛光只出现在收件箱 30 分钟内有信的账号行；临时让程序启动后切到浅色，界面、标题栏变浅，正文查看器重建后显示原色。刷新：账号连到只接受连接、不回应的本地端口时，按 F5 后按钮一直转圈；单元测试 `imap::tests::catches_mail_between_commands` 验证 IDLE 中的连接收到刷新后立即再全量同步。拖动排序用投递的鼠标消息模拟不出来，由用户实测。
4. **链接与追踪器**：点击链接先显示真实地址、去跟踪参数、拆已知跳转壳，再用自选浏览器打开；标出追踪器来源；按封 / 按发件人白名单加载图片；关掉 WebView2 自己的后台联网（组件更新等，启动后数据目录里会出现组件缓存）。
   - 链接：点链接弹对话框，显示清洗后的地址；改过时另列原地址、拆掉的跳转壳、去掉的参数，按钮为打开 / 打开原地址 / 复制 / 取消。只拆地址里直接带着目标的壳（Google、Outlook SafeLinks、Facebook 等）；Mailchimp、SendGrid 这类目标存在对方服务器上的点击追踪不去访问，原样显示。跟踪参数用内置名单，不可自定义。`mailto:` 和相对地址只显示、复制（第六步后 `mailto:` 改为打开写信）。纯文本邮件里的 http(s) 网址补成链接，句末标点不算进网址；邮件地址不补。
   - 浏览器：左栏底部“浏览器”菜单，全局一个：系统默认；指定一个程序（只传网址这一个参数，系统文件选择框选 exe）；或 AdsPower 环境。SunBrowser 由 AdsPower 带着环境的指纹和代理启动，直接运行 exe 会裸连，所以走 AdsPower 本地 API（`127.0.0.1:50325`，`Authorization: Bearer <API key>`）：环境没开就让 AdsPower 按它自己的设置打开，再经环境的调试端口 `/json/new` 开新标签页。刚关掉的环境在 AdsPower 收尾的几秒里仍报 Active，调试端口却已关闭：调试端口连不上时每隔约 1 秒重查，等它报 Inactive 再打开，最多重试 10 次；开标签页的请求发出后不重发，免得重复打开。调试端口回完不断开连接（不理 `Connection: close`），响应正文按 `Content-Length` 读。填环境 ID 和 API key，key 存凭据管理器。
   - 追踪器来源：阅读区头部列出拦下 / 已加载的远程资源的域名及次数；不内置“域名→公司名”的追踪器名单。
   - 图片：清洗时远程图片地址（含 CSS 里的 `url()`）全部换成本地编号地址，查看器内核见不到远程域名，不会预解析、预连接。允许加载时由 MailPro 经该邮箱的代理代取（不带 cookie、Referer，User-Agent 用通用值），没设代理的邮箱直连；只放行图片类，字体、样式表、音视频照样拦。按封允许只管这一次查看；按发件人记进数据库，按 From 地址匹配，不分大小写（From 可伪造，冒充名单里发件人的邮件也会自动加载）。图片不缓存，每次加载对方都知道又打开了一次（看到的是代理 IP）。命令行打开的 .eml 不属于账号，不给加载。
   - 后台联网：WebView2 启动参数 `--disable-background-networking --disable-component-update --disable-domain-reliability`。
   - 代码：`crates/core` 的 `link`（拆壳、去参数）、`http`（经代理的最小 HTTP/1.1 GET，和 IMAP 共用 `imap::tcp` 出站）、`sanitize`（远程图片换本地地址）、`store` 的 `image_sender` 表；`crates/app` 的 `browser`（启动浏览器）、`webview`（远程图片请求挂起，交给界面决定是否代取）。
   - 验证：emailprivacytester.com 的测试邮件逐项无触发；运行十分钟内 WebView2 进程没有对外连接；链接在选定的浏览器里打开。
   - 现状：
     - emailprivacytester 的测试邮件在 MailPro 里打开后，结果页的 IP、User-Agent、触发项都没有变化。点“加载图片”后才多出代理出口 IP 和通用 User-Agent，进程只连了 127.0.0.1:7898。
     - 用新数据目录跑十分钟：WebView2 进程没有一条对外 TCP 连接，也没有 UDP 端点；数据目录里没有出现组件缓存（CertificateRevocation、Subresource Filter 等）。
     - `tracking.eml` 计数服务器命中仍为 0。
     - 按发件人加载已在真实账号上实测：记库后重新打开会自动加载，取消后恢复拦截。
     - 链接在 AdsPower 环境里打开、环境关闭后自动拉起，均由用户实测通过。纯文本确认邮件的网址都成了链接（截图核对）。
     - 真实数据目录里加启动参数前留下的组件文件夹已删除。
5. **邮件操作**（已完成）：删除、归档、移动、标星、标已读 / 未读、整个文件夹标为已读，结果写回服务器。
   - 选择：点一封即选中并打开；Ctrl 点增减一封、Shift 点从上次点的那封选到这封，都不打开，阅读区显示选了几封和操作栏。
   - 入口：阅读区头部的操作栏（多选时在阅读区中间）；列表行右键菜单，右键没选中的行先选中并打开它；列表顶部“全部标为已读”按钮，文件夹有未读时显示。右键菜单开着时正文藏起，否则盖在正文上的菜单项点不到。
   - 标记（已读、星标）：先改本地并记待写回（`pending` 表按位记改过的标记和新值），同步该文件夹时写回，离线也能改。
   - 归档：移到归档文件夹，没有就移到所有邮件（Gmail 的归档即去掉当前标签）；正在看的就是它时不显示。删除：移到已删除；已在已删除里，或账号没有已删除文件夹时彻底删除，先确认。移动：对话框里选账号内的其他文件夹。
   - 移动类的执行：本地先删，引擎再用 IMAP MOVE 在服务器上移；服务器不支持 MOVE 时退回复制 + 标删除 + UID EXPUNGE，只清这几封（要 UIDPLUS，否则报错）。成功后同步目标文件夹；失败时提示原因并重新同步原文件夹，邮件回来。账号断线时不动，提示没连上。移走正在看的邮件后阅读区清空，不自动打开下一封。
   - 代码：`crates/core` 的 `imap::move_to`、`store::mark`；`crates/app` 的 `view`（`Act` 为各项操作）。
   - 验证：GreenMail 测试（`crates/core/tests/sync.rs`）覆盖星标写回、移动、彻底删除；界面用测试库截图核对右键菜单、操作栏、移动对话框、全部标为已读、断线时删除的提示。
   - 现状：以上验证通过。多选（Ctrl / Shift 点无法用投递的消息模拟）、右键菜单开着时正文藏起、真实 Gmail 上的移动 / 删除 / 归档由用户实测。
6. **写信与发送**（已完成）：纯文本写信、回复、全部回复、转发，经邮箱的代理连 SMTP 发出（lettre）。587 端口走 STARTTLS，服务器不支持就报错，不明文发；其他端口隐式 TLS。Outlook 用 XOAUTH2，其他用密码。
   - 入口：列表顶部的写信按钮；阅读区头部的回复、全部回复、转发（正文到了才显示）；正文里的 mailto: 链接（RFC 6068 的收件人、抄送、密送、主题、正文）；点草稿文件夹里的一封接着写。写信框是对话框。
   - 发件人：默认正在看的那封所属的账号，否则选中文件夹的账号；多个账号时可在下拉里换。显示名取账号设置里的“发信名字”，空则只写地址。
   - 收件人：默认只显示收件人一栏，“抄送 / 密送”展开另两栏（打开时已有内容自动展开）；逗号或分号分隔，不做自动补全。
   - 回复：回给 Reply-To，没有就回发件人；全部回复再加原收件人和抄送；都去掉自己和重复的，回自己发的信时改回给原收件人。主题加 `Re: `；正文上方留空，下面是“{时间}，{发件人} 写道：”和逐行加 `> ` 的原文；带 In-Reply-To、References；发出后原信标已回复（`\Answered`）。转发：主题加 `Fwd: `，正文带原信头部（发件人、日期、主题、收件人、抄送）和原文，不带附件。写信不能加附件。
   - 发信头脱敏：EHLO 报 `[127.0.0.1]`；Message-ID 是 32 位随机串加发件人的域名；Date 一律 UTC，回复、转发引文里的时间也用 UTC；不带 User-Agent / X-Mailer。发出的那份不带 Bcc 头，存进已发送 / 草稿的那份带。
   - 已发送：Gmail 自己存；其他邮箱（含 Outlook，它若自己也存会多一份，待实测）发出后 IMAP APPEND 一份进已发送文件夹（标已读），没有已发送文件夹就不存。
   - 草稿：关掉写信框（Esc、右上角关闭）时内容或发件账号改过就存进草稿文件夹（`\Draft \Seen`），不问；存好才关，存不了（账号没连上、没有草稿文件夹、地址有误）时提示原因、窗口留着，可以点丢弃。接着写的旧草稿在发出、存了新的或丢弃后删掉：有所有邮件文件夹的账号（Gmail）移到已删除，否则彻底删除。由回复存成的草稿接着写后发出，不再给原信标已回复。
   - 发送：先查地址、收件人、账号连着没有；超时 60 秒；失败时提示原因，窗口留着可以重试。发送、存草稿中按钮置灰，关不掉。
   - 账号设置：发信名字、SMTP 服务器和端口（Gmail、Outlook 固定，不显示）；SMTP 服务器留空时按 IMAP 服务器推（`imap.` 换成 `smtp.`），端口默认 465。
   - 代码：`crates/core` 的 `smtp`（拼信、发信、mailto）、`message::original`（回复、转发、草稿用的原信内容）、`imap::append`、`engine` 的 `Cmd::Send` / `Cmd::Append`；`crates/app` 的 `view/compose.rs`。
   - 验证：`smtp::tests`（头部脱敏、地址拆分和拼回、mailto）、`message::tests::prepares_replies`；GreenMail 测试 `sends_and_saves_drafts`（明文 SMTP 发信：EHLO、无 Bcc 头；存草稿后同步看得到，带 Bcc、已读）；界面用测试库截图核对全部回复和转发的预填与焦点、改过后关闭时的提示、丢弃、展开抄送密送、换发件账号、接着写草稿、账号设置的新栏位及保存。
   - 现状：以上验证通过。真实邮箱的发信（TLS、代理）、存已发送、存草稿和删旧草稿由用户实测。
7. **本地搜索**（已完成）：列表顶部的搜索框，搜本地已同步的邮件头（主题、发件人名字和地址），不搜正文。
   - 匹配：按空格分词，每个词都要出现（可以分在主题和发件人里），不分大小写只限英文字母；`%`、`_` 按字面。新的在前，不限条数。打字停 300 ms 再搜，清空时马上回到文件夹列表。
   - 范围：搜索框右边的按钮切换“当前文件夹 / 全部邮箱”。全部邮箱即所有账号的所有文件夹，但有“所有邮件”文件夹的账号（Gmail）只搜所有邮件、垃圾邮件、已删除，每封只出现一次；结果每行标出所在文件夹，多个账号时再带上邮箱。
   - 搜索中：列表顶部的“全部标为已读”不显示（它标整个文件夹）；全部邮箱的结果里只能在同一个文件夹内多选，Ctrl 点别的文件夹的邮件就从它重新选起；点左栏的文件夹清空搜索。同步到新改动时结果跟着刷新。
   - 实现：SQL `LIKE` 全表扫描，5 万封 17–40 ms（全部命中时 119 ms，主要是取出和排序），在后台线程跑，不建 FTS 索引。代码：`store::search`；`view` 的 `load`、`search_folders`、`picked_in`。
   - 验证：`store::tests::search_matches_every_word`；界面用测试库截图核对当前文件夹无结果、全部邮箱的混合结果和文件夹标注、打开结果标已读、点文件夹清空、切换语言后提示文字。
8. **收尾**：设置导出 / 导入、图标、安装包、README。
   - 安装包：Inno Setup 按当前用户安装（`scripts/installer.ps1`，产物只留当前版本）；卸载时删数据目录 `%LOCALAPPDATA%\MailPro`，并运行 `mailpro.exe --purge-credentials` 删凭据管理器里 `MailPro/` 开头的全部凭据。图标为粉色信封带封蜡锁孔（`scripts/icon.py`）。
   - 现状：图标、安装包、README（英文为主，附中文版）、第三方许可声明已完成，0.3.0 发布在 GitHub Releases；设置导出 / 导入未做。

## 托盘与新信通知

- 托盘：点窗口的关闭按钮只是藏起窗口，图标留在通知区域，继续收信；最小化照常缩到任务栏。左键点图标唤出窗口；右键菜单为打开 / 退出；悬停显示各收件箱未读数之和。同一份数据（数据库路径）已有实例在运行时，再启动即唤出原窗口，新进程退出。不做开机自启。
- 通知：只看收件箱，启动后（新加的账号从首次列出文件夹起）收到、未读、uid 比已看过的大的才弹；首次同步、补拉的旧信、其他文件夹（含垃圾邮件）不弹。窗口在前台时不弹。一封显示发件人和主题，点开即打开它；同一次同步到多封合成一条“N 封新邮件”，标题是邮箱，点开打开该收件箱。点通知只认最近弹的一条。不另设开关，用 Windows 设置 → 系统 → 通知关闭。用托盘图标的气泡通知（Shell_NotifyIcon），Windows 10/11 显示成右下角的通知，不加依赖。
- 代码：`crates/app` 的 `tray`（隐藏窗口、图标、菜单、通知、唤起已有实例）、`view` 的 `notify_new`、`on_tray`；`crates/core` 的 `store::fresh`。
- 验证：`store::tests` 覆盖新信查询；私有桌面上（不碰用户的屏幕和键盘）测关窗口后藏起、再启动唤出原窗口且新进程退出、点图标和点通知唤出、右键菜单退出；真实任务栏上图标加上（`Shell_NotifyIconGetRect`），启动不抢前台。断线修复：6 个真实账号经 Clash 7898 挂 `mailpro-cli watch` 210 秒零断线，中途两次查看连接，同样 6 条、本地端口不变。
- 现状：通知的弹出、点开打开那封、悬停提示的文字、菜单文字由用户实测。

## 已知限制

- gpui 的画面盖在子窗口之上：窗口背景用 Transparent，正文区域不画背景，WebView2 才透得出来。反过来，gpui 画在正文区域上的弹层（菜单、对话框）会盖住正文，弹层本身要画不透明背景。
- 服务商（Google、微软）能看到全部邮件内容，只有端到端加密挡得住，不在本工程范围。
